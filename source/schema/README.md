# Input and exchange schemas

`source/schema/` stores machine-readable shapes. It does not own the authored product API/database contracts (maintained in repository-root [`dryv/`](../../dryv/README.md)) and it holds no SQL: generated database artefacts live with their owner, [`source/backend/database/`](../backend/database/README.md). The layout was approved on 16 November 2026 as part of the schema and manifest redesign (`.docs/todo/work/W47/schema-and-manifest-redesign--600e51/`). No folder or file name carries a version (`.docs/rules/versioning.md`).

| Folder | Contents | How it is kept |
|---|---|---|
| `database/` | One `<group>.schema.json` per PostgreSQL group: each table's columns, types, nullability, primary and unique keys, enum values and foreign keys (`references.tableId` names the target table's `id`). Seed CSV files and mappings are validated against these. | Generated by Dryv (`bun run catalog`). Never edit by hand. |
| `seed/` | `manifest.schema.json` (seed registry), `folder.schema.json` (`_folder.yaml`), `bootstrap.schema.json`. | Hand-written. |
| `sources/` | `source.schema.json` is the entry for one source manifest (header plus `website.schema.json` or `api.schema.json` by `kind`); `module.schema.json` describes discovery and extraction; `common.schema.json` holds shared definitions. Plural on purpose: these are authored source manifests, not the database `source` group. | Hand-written. |
| `mapping/` | `mapping.schema.json`: turns a module's extracted fields into records for real tables (`yields`), with `ref` between yields and `lookup` of existing rows. | Hand-written; the validator checks tables and columns against `database/`. |
| `vocabulary/` | `web.schema.json` and `web.yaml` (web classification data read by `mzizi-fetch`), and `terms.schema.json` (named term lists). | `web.schema.json` is generated from the typed model; a test keeps it in sync. |
| `engine/` | `job.schema.json`: the job spec the engine parses. | Generated from the typed model; `MZIZI_WRITE_SCHEMAS=1 uv run pytest source/backend/engine/tests/runs/test_job_schema.py` regenerates it. |
| `extraction/` | `table.schema.json`: optional expected columns for PDF table comparison. | Hand-written. |

Every folder has an `_example/` folder with valid documents. Each example names the schema it defines, so an editor validates it: YAML files start with `# yaml-language-server: $schema=<relative path>` and JSON files carry a `"$schema"` key. Real files should do the same. `database/_example/` shows seed CSV files and their path rule.

The previous site-bundle schemas (`site/v1/`), target catalogue and hand-kept exchange schema were retired on 16 November 2026; copies are in `.dev/archives/schema-retired/` on the machine that removed them and in Git history. The crawler's bundle validator now reads `sources/`, `mapping/` and the generated `database/` schemas.

`bun run catalog` regenerates `database/`. Change contract-derived files through `dryv/`. Change SQL through reviewed releases. Do not copy publisher- or country-specific values into these generic schemas.

`uv run pytest source/packages/manifest/tests/test_schemas.py` checks that every schema is valid and that each accepts and rejects the documents it should.
