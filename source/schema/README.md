# Input and exchange schemas

`source/schema/` stores machine-readable shapes. It does not own the authored product API/database contracts (maintained in repository-root [`dryv/`](../../dryv/README.md)) and it holds no SQL: generated database artefacts live with their owner, [`source/backend/database/`](../backend/database/README.md). The layout was approved on 16 November 2026 as part of the schema and manifest redesign (`.docs/todo/work/W47/schema-and-manifest-redesign--600e51/`). No folder or file name carries a version (`.docs/rules/versioning.md`).

| Folder | Contents | How it is kept |
|---|---|---|
| `database/` | One `<group>.schema.json` per PostgreSQL group, a real JSON Schema with an `$id` and a `code` (`global.database.<group>`). Each table is a row schema under `$defs`: its stored columns, each with an `x-role` (`key`, `data`, `link` or `system`), plus `x-code`, `x-table`, `x-primaryKey`, `x-uniqueKeys`, `x-naturalKey`, `x-seedable`, and `x-seed`, the shape of a seed row: allowed and required columns, with each foreign key written as the target's code (`x-link.alias`, such as `scheme_code`) and the system columns (`id`, `version`, audit dates; `.system()` in the contracts) listed as never allowed in a seed. Seed CSV files and mappings are validated against these through `mzizi_manifest.features.database.tables`. | Generated by Dryv (`bun run catalog`). Never edit by hand. |
| `seed/` | `manifest.schema.json` (seed registry), `folder.schema.json` (`_folder.yaml`), `bootstrap.schema.json`. | Hand-written. |
| `sources/` | `source.schema.json` is the entry for one source manifest (header plus `website.schema.json` or `api.schema.json` by `kind`); `module.schema.json` describes discovery and extraction; `common.schema.json` holds shared definitions. Plural on purpose: these are authored source manifests, not the database `source` group. | Hand-written. |
| `engine/` | What the engine consumes to process data: `job.schema.json` (the job spec), `mapping.schema.json` (turns a module's extracted fields into records for real tables with `yields`, `ref` and `lookup`; checked against `database/`; an input can also state the expected column of a PDF or spreadsheet table, so expected columns live here and not in a manifest of their own) `web.schema.json` (the web classification data read by `mzizi-fetch`; the data is `seed/engine/web/classification.yaml`; generated from the typed model with `MZIZI_WRITE_SCHEMAS=1 uv run pytest source/packages/fetch/tests/test_web_core.py`) `terms.schema.json` (term lists: groups of words, patterns, heading rules and splits, one list per scope and domain, `seed/terms/<scope>/<domain>.yml`) and `columns.schema.json` (column dictionaries: which term groups, patterns and heading rules define each seed column, how a table's code is proposed, and where its known names come from; `seed/columns/<scope>/<domain>.yml`). A mapping's code follows the database hierarchy, not this folder. | `job.schema.json` is generated from the typed model (`MZIZI_WRITE_SCHEMAS=1 uv run pytest source/backend/engine/tests/runs/test_job_schema.py`); the mapping and terms schemas are hand-written. |

## Public URLs

Every schema is served anonymously at `https://res.alidantech.org/mzizi/public/schemas/<folder>/<name>.schema.json` (object key `public/schemas/<folder>/<name>.schema.json`; only `public/` is anonymously readable). A schema's `$id` is that URL, so relative `$ref`s and editor links resolve there. Resync everything after changing a schema, with no database involved:

```bash
bun run schemas:sync
```

It regenerates the Dryv table schemas and the job schema, runs the schema and example checks, then uploads what changed. `-- --local` stops after the checks, `-- --dry-run` lists the keys that would be uploaded, and `-- --no-dryv` skips the Dryv generation. The upload alone is `uv run mzizi-engine publish-schemas` (`--dry-run` lists the keys without connecting; objects under the public prefix that no schema produces any more are reported as orphans and deleted only with `--prune`). The command uploads only changed files, then reads each public URL anonymously and fails if it does not return the same bytes. These objects are not registered in the filesystem tables. Plain HTTP responses carry no CORS headers, which editors do not need.

**Editors cache downloaded schemas.** The Red Hat YAML extension keeps them on disk and never refetches a cached URL; the JSON extension keeps them in memory. After publishing, run `bun run schemas:forget-cache` (removes only the cached copies of our schemas), then in the editor run "JSON: Clear Schema Cache" and "Developer: Reload Window". Without that an editor can keep reporting "Property code is not allowed" from an old copy.

Every folder has an `_example/` folder with valid documents. Each example names the schema it defines, so an editor validates it: YAML files start with `# yaml-language-server: $schema=<public URL>` and JSON files carry a `"$schema"` key. Real files should do the same. `database/_example/` shows seed CSV files and their path rule.

The previous site-bundle schemas (`site/v1/`), target catalogue and hand-kept exchange schema were retired and will not return on 16 November 2026; copies are in `.dev/archives/schema-retired/` on the machine that removed them and in Git history. The crawler's bundle validator now reads `sources/`, `engine/mapping.schema.json` and the generated `database/` schemas.

`bun run catalog` regenerates `database/`. Change contract-derived files through `dryv/`. Change SQL through reviewed releases. Do not copy publisher- or country-specific values into these generic schemas.

`uv run pytest source/packages/manifest/tests/test_schemas.py` checks that every schema is valid and that each accepts and rejects the documents it should.

## Codes and references

Every code follows `.docs/rules/codes.md`: a space (`pg` row, `sys` system thing, `mg` reserved), fixed schema and table shorts from `source/schema/seed/codes.json`, dots for "narrower than", dashes for the words of one name, no underscores. Website and API sources use `pg.src.srs.<scope>.<name>`; a mapping `sys.map.<schema>.<table>.<scope>.<name>`; a term list `sys.trm.<scope>.<domain>`; a column dictionary `sys.col.<scope>.<domain>`; a job `sys.eng.job.<scope>.<name>`; engine data `sys.eng.<name path>`. A source names the others in `uses` (`mappings`, `terms`) and `extends`; a module names a mapping. `uv run mzizi-manifest refs [folder]` (default `seed/`; `source/schema --no-paths` for the flat examples) checks codes against the glossary, the kind rules, that a file's folder path mirrors its code, and that every reference resolves: unknown, duplicate, wrong-kind, other-country and global-to-country uses and cycles are errors, each naming the file, the field and the code. `uv run mzizi-manifest data [folder]` checks seed CSV files, where a code or link cell is the identity path alone.
