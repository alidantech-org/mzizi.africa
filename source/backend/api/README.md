# Mzizi API (NestJS)

The Mzizi product API. It reads and serves canonical data and has only three kinds of writes: comments, evidence references and role-gated review decisions. It does not scrape, clean, extract, migrate or seed; those belong to `source/backend/data-engine`, `intelligence`, `files` and `db-engine` (see `.docs/docs/ARCHITECTURE.md` section 7).

Nearly everything under `src/modules`, `src/types`, `src/app.module.ts` and `src/database` is generated by Dryv from the contracts in the repository-root `dryv/` folder, using the same structure and packs as the Alidantech backend. Files marked "Scaffolded by Dryv once" (use cases, service implementations, `database.module.ts`, `vitest.config.ts`) belong to the project and are where hand-written logic goes. See `dryv/README.md` for the generation workflow. The inherited Python service lives in `source/backend/api-legacy`.

## Run and test

```bash
bun install
DATABASE_URL=postgres://reader:pw@localhost:5432/mzizi bun run dev
bun run typecheck
bun run test
TEST_DATABASE_URL=postgres://postgres:test@localhost:55432/mzizi bun run test   # adds the PostgreSQL integration test
```

## Database access

`DATABASE_URL` must point at a role with SELECT only on the domain tables. `synchronize` is false and the app has no migrations or seed path, so it cannot change schema; schema is owned by `source/backend/db-engine`. The integration test creates its own scratch schema and a SELECT-only role to prove the read slice works without write access.
