# Migrations

One immutable release stream for the single database `mzizi`. `bun run db assemble` writes `0001_init.sql` from the generated snapshot (`sql/schema.sql`) and records its SHA-256 in `.snapshot`. `bun run db migrate` applies each release in one transaction together with its row in `public.mzizi_migrations`; a changed checksum is refused forever after. Do not edit committed releases. Details: [database README](../README.md).

## Releases

- `0001_init.sql`: every table, index, constraint and extension, assembled from the Dryv-generated snapshot. The stream was reset on 17 November 2026 (twice that day) when the Filesystem, Source, Geography and Legal ownership redesign changed the schema; the earlier `mzizi`, `mzizi_dev`, `mzizi_new` and `mzizix` databases were recreated from it, so any earlier ledger is obsolete.
- `0002_subject_integrity.sql`: generated by `dryv/tools/subject-integrity.ts` (`bun run subjects:check` in `dryv/` fails when it is stale). Dryv emits the shared subject keys as plain `text` and `uuid`, so this release adds the integrity Dryv cannot express: a CHECK on the carrier tables (`filesystem.media`, `legal.effects`, `source.relationships`, `source.verifications`, `source.citations`) that `subject_table` is a `SubjectTable` member, a before-write trigger that the named subject row exists, and a before-delete RESTRICT trigger on every subject table so a referenced row cannot be hard-deleted (soft deletion is unaffected). The existence function only reaches `regclass` after the table name passed the enum check.

## Later releases

Schema evolution releases are not generated yet. A change to the contracts after the stream is deployed needs a hand-written next numbered release; check on a scratch database that the earlier releases plus the new one equal the regenerated snapshot, then record the new snapshot checksum in `.snapshot`. `bun test` fails if the record and the snapshot disagree. While the database is still disposable, regenerate the snapshot, delete the releases, run `bun run db assemble` and `bun dryv/tools/subject-integrity.ts`, and recreate the database.
