# TypeScript database service

This service owns application writes, schema lifecycle, seed loading, and controlled promotion. The Bun CLI applies ordered SQL through TypeORM with checksums, can adopt checksum-verified history from the former Python ledger, and restricts migration/reset targets to local `mzizi_new`. The internal API provides named audit, authorization (including scoped filesystem checks), folder creation, and pipeline persistence operations. Runtime roles are created as no-login groups; application logins must be granted the appropriate group by local provisioning. Python filesystem reads and operations other than folder creation, engine persistence, identity fallback, and seed synchronization still contain PostgreSQL paths, so the single-writer cutover is not complete.

Run `bun run db status`, `bun run db migrate`, or `bun run db seed` from the repository root. The CLI uses `MZIZI_DATABASE_URL` when set and otherwise targets local `mzizi_new`; it deliberately ignores the API's general `DATABASE_URL`. After migration, `bun run db provision-local-roles` creates the least-privilege local service logins. The database service uses `DATABASE_RUNTIME_URL`; the product API uses a separate SELECT-only `DATABASE_URL`; the administrative URL stays with the CLI. `bun run db reset --confirm mzizi_new` rebuilds only that disposable local database and seeds auth/reference. `bun run db seed pipelines <actor-uuid>` reads only entries allowlisted as `database.pipeline-release` in `seed/manifest.yaml` and proposes each immutable release through the service; activation remains a separate operation requiring the expected content hash. `bun run db bootstrap-admin` creates the first local administrator from explicit arguments or the `AUTH_BOOTSTRAP_*` environment variables. The Python database package remains present until every active caller has a replacement. Do not treat the transition as complete while any runtime still connects directly to PostgreSQL for writes.
