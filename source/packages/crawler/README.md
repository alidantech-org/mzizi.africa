# mzizi-crawler

All web acquisition in one package, behind `CrawlerOrchestrator`: polite, identified crawling with a resumable frontier; selectors, transforms, link and reference discovery, fingerprints and change detection (`shared/scraping`); scraping from manifests; survey and draft bundles; sections and listings; attachment selection and ranking; safe downloads and queues; replay of saved captures; inspection of single pages; site watching (`site`, `batch`, `changes`) with a hashed, versioned site store; and site-structure bundles (`shared/bundles`). Search by scraping result pages belongs here too; API-based search stays in `mzizi-search` for later.

It never opens a database. Records go to an optional activity store behind the `Activity` port (`shared/activity.py`); the engine wires a MongoDB implementation with `configure_activity`. The local evidence layout and deterministic names are `shared/layout.py` and `shared/names.py`. Browser work is `mzizi-browser`.

Layout: `shared/` (requests and records, `engine/` the crawl engine, `scraping/`, `bundles/`, the site store, hunting, pipelines, export, identity, layout, names, activity port) and `features/<name>/` (`crawl_site`, `scrape`, `survey`, `sections`, `attachments`, `rank`, `inspect`, `replay`, `downloads`, `queue`, `site`, `batch`, `changes`). Tests use a loopback site (`tests/web_site.py`); real-Chrome tests skip when Chrome is absent. Known debt: regular expressions and constant tables that belong in manifests and the pattern-matching package, and the lax typing of `shared/bundles` (listed in the root mypy overrides).
