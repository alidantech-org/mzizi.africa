# Mzizi SDKs

Client SDKs generated by Dryv from the product API contract (`dryv/contracts/apps/api`). Each holds every API operation. The web UI is handwritten and consumes the shared generated server client directly; the app and dev frontends retain their own generation contracts. Apps import these packages and never carry or invent client code. Do not edit generated files: change the API contract or the project packs in `dryv/packs/sdk-ts` and `dryv/packs/sdk-dart`, then regenerate.

| Folder | Package | Used by | Contents |
| --- | --- | --- | --- |
| `api-ts` | `@mzizi/api-client` | Next.js apps (`web`, `dev`) | resource actions, one `routes.ts`, nested DTOs/enums |
| `api-dart` | `mzizi_api` | Flutter app (`app`) | feature clients, endpoints, models |
| `ui/web` | `@mzizi/ui-web` | generated Next.js clients (`dev`) | hand-written visual components assembled by generated screens; the independent web UI owns its components |
| `ui/flutter` | `mzizi_ui` | Flutter app (`app`) | hand-written visual components (not generated) |
| `ui/brand` | n/a | brand scripts | icon source and mark |

Imports inside the SDKs are absolute: `#sdk/` in TypeScript (package.json `imports`, distinct from the apps' `#/` alias so both resolve in one build) and `package:mzizi_api/` in Dart.

Regenerate with `bun $DRYV_HOME/source/apps/cli/bin/dryv.ts generate --app api --pack sdk-ts --pack sdk-dart`.

The TypeScript client's `src/` follows the DefyTickets `server/` layout: one `routes.ts`, resource action modules under `actions/` with an index, runtime utilities under `helpers/`, and `types/<resource>/{dto,enums}` with category/resource/root indexes. `src/index.ts` exports only client-safe routes and types. No `v1.ts`, version folders, per-operation action folders, router folders or compatibility aliases are generated.

Import requests from `@mzizi/api-client/actions` or `@mzizi/api-client/actions/explorer`. Function names combine group and operation, for example `explorerGetExplorerContext`; transport inputs use `ExplorerGetExplorerContextActionInput` to avoid collisions with body schema names. The server bridge is configured with `SERVER_URL`. Existing frontend imports are migrated separately; this checkpoint does not supply shims for their former calling convention.

From the repository root run `bun run typecheck --only sdk-ts` and `bun test scripts/sdk-client.test.ts`. These checks cover generated types, all registered API routes, encoded identities, the public server/client boundary and the resource directory structure without depending on a frontend application. See [the pack guide](../../dryv/packs/sdk-ts/README.md).
