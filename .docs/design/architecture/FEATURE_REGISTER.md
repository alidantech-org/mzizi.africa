## A. Abbreviations (F26)

- **Already in the model:** `official.names` carries a name kind and language; the seed has the kind `ofc.name.kind.abbreviation` (and short and official); `legal.names` has an abbreviation kind; `reference.value_labels` and `reference.language_names` have abbreviation kinds. The structure exists; what is missing is the data, the read logic and the display rule.
- **Display rule:** every list, card, breadcrumb, search hit and title shows `Full name (ABBR)` when an abbreviation exists in the display language, falling back to the shared (`mul`) form; no abbreviation, no brackets. The composed reads return the pieces (`name`, `abbreviation`) and a generated name component renders them, so no page assembles the string by hand.
- **Scope:** institutions (IEBC, ORPP, KNBS, KEBS), parties, state bodies, suppliers and contractors, schools and facilities, laws (for example procurement and electoral acts), funds and programmes, and any `official.entities` or `individuals` where one exists.
- **Search:** the abbreviation is searchable and an exact abbreviation match ranks first.
- **Data:** abbreviations are sourced and cited, never invented; a coverage check lists entities of the listed kinds with no abbreviation and no "has none" mark.
- **Cautions:** abbreviations repeat across countries and sometimes inside one, so they are shown with context and never used as identifiers; the slug is separate.

## B. Media on listed things (F27)

- **Already in the model:** `filesystem.media` (kind: logo, symbol, flag, portrait, photograph, audio, video, document scan; display `position`; purpose; alt text; stored bytes or an external URL) attached to any subject, plus `filesystem.tags` and `taggings`, and `official.branding`.
- **Rule for lists:** each list item gets a **lead media** chosen by kind rank, then position: a flag first for a country, county or other place that has one, then a logo or symbol for parties and institutions, then a portrait for a person, then photographs and famous points. The rank per kind is data on the media kind values, not a UI constant. No media means a neutral generated placeholder, never a broken image.
- **Tags** decide extra groupings (famous points, landmarks, symbols) and feed search filters.
- **Alt text and licence** are required for display; media without a licence status stays hidden.

## C. Explore by topic (F28)

- **Topics** already exist as `reference.topics` (and indicators and content carry a topic). The Explore page becomes a **topic navigator**: one card per topic (politics, elections, population and statistics, money, infrastructure, law, parliament and others), each showing a lead media (party symbols for politics, banknotes for money, people for population), a short intro, counts of what exists, what changed recently and entry links into the section pages.
- **Tracker role:** each topic card can show recent activity (new data, new events, updates) for the visitor's context, so the topic also works as a "what is new here" tracker.
- **Search:** the same topics are facets on the search page and give search results their topic media.
- **Media for topics:** topics are subjects, so media attach to them like any other subject.

## D. Fun facts as content (F29)

- A fun fact is a `filesystem.contents` row of category `fun-fact`, attached to a subject (a country, place, person, institution, topic), with its own media. No separate schema. The category value (scheme `fil.content.category`) is added through the seed with the owner's approval.
- **Inheritance:** a fact tagged to a place shows on that place and the places inside it; a country fact shows everywhere in the country (the earlier `facts` behaviour, kept).
- **Carousel:** the context returns the facts for the visitor's place in a stable order; two or more make an **auto-swiping carousel** (pause on touch and hover, controls for keyboard and screen readers, respects reduced motion); one is a static tip.
- **Evidence:** a "checkable" fact cites its source through the standard citation by subject mechanism; unsourced facts are marked as development text, as `contents` already allows.

## E. Removed for now (F30)

- `dryv/contracts/schemas/postgres/audit.ts` is removed. If audit returns it belongs in `source` or `auth`; it is not added now.
- `dryv/contracts/schemas/postgres/facts.ts` is removed with its `ListFacts` operation (a new, simpler design replaces it, see D).
- Consequences still to handle in the generation step: regenerate (the `facts` and `audit` schemas, their API, engine and SDK output disappear); a new database migration drops the schemas and the development database is reset; the closed subject list loses `facts.facts` and `facts.fact_places` through `tables:sync`; the hand-written `reads/facts.ts` and `list-facts.usecase.ts`, the web `fact-strip` and `insights.ts` fact reads, and the Flutter facts screen and paging must move to content-backed fun facts; the `audit` store mention in the contract descriptions was already removed.
