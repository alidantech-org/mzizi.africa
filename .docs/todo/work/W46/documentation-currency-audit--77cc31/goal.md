# Audit the project documentation set

## Goal

Assess active `.docs/docs` material against the current package-first repository so maintainers can keep a small, trustworthy set of overall system guidance and identify historical or stale material. The audit focuses on whether each document has a current purpose, matches current code ownership and paths, contains useful current instructions, or should be kept as a clearly labeled historical record, revised, consolidated, or removed. It must identify links to missing code and stale claims such as superseded service paths, database counts, country-specific assumptions and former seed locations.

## Success

Provide a file-by-file disposition grounded in repository references and current source paths. Preserve the six purpose/architecture/lifecycle/domain/migration documents that AGENTS.md explicitly requires unless evidence shows they should be replaced together. Do not delete documentation during the audit; any deletion or archival proposal remains for separate action. Record broken and stale internal references, cross-document dependencies, and the minimum set of overall-system documents to retain.
