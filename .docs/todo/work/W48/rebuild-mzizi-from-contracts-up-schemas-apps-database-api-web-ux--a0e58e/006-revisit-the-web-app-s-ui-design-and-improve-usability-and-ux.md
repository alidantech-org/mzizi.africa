# Revisit the web app's UI design and improve usability and UX

## Goal

Once the real app works and is fast, review it as people will use it: is it clear, accessible, usable on a phone and on a slow connection, and does it help people understand their government and history. Plan and make the improvements.

## Context

Task 6 of 6, the last in the wave; starts only when task 5 is completed. Keep the accessibility rules in the web README (semantic HTML, keyboard focus, contrast, reduced motion) and the navigation rules. Changes are design and usability improvements, not new data features; new data needs go back into contract tasks in a later wave.

## Review

- [ ] Walk every screen on desktop and phone and record usability problems
- [ ] Accessibility audit (keyboard, screen reader, contrast, text size)
- [ ] Check slow-network behaviour and loading states
- [ ] Gather owner feedback and rank the problems

## Plan

- [ ] Write the UI/UX improvement plan with priorities
- [ ] Agree visual system changes (spacing, type, colour, components)

## Build

- [ ] Navigation and wayfinding improvements
- [ ] Readability of evidence, sources and uncertainty
- [ ] Map and chart usability
- [ ] Forms, preferences and saved items
- [ ] Phone layout fixes

## Acceptance checklist

- [ ] Every ranked problem is fixed or deliberately deferred with a reason
- [ ] Accessibility audit passes
- [ ] Speed from task 5 is not made worse
- [ ] Docs updated and `task validate` passes
