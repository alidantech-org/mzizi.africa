# Mobile app alignment

## Goal

Bring the Flutter client into line with Mzizi Africa's evidence-first public product and the current NestJS/API direction. The mobile app should help people explore verified knowledge across place, time, heritage and public life while consuming stable API contracts. It must not introduce canonical facts, boundaries or provenance locally. The group succeeds when each mobile screen has an agreed data owner and contract, current static samples are removed or clearly labeled as a prototype, and public evidence can be inspected with dates, sources, uncertainty and links to related knowledge.

## Scope

This group covers the Flutter public client in `source/apps/mobile`, its API contract and product documentation, and the client-facing integration needed to make mobile a useful Mzizi experience. It does not move extraction, AI review, canonical data rules or database lifecycle responsibilities into the app.
