# Goal

Make every manifest, schema and seed input in Mzizi small, current and easy to understand, and make the manifest package verify them against approved designs instead of against its own code. Today about eighteen schema files, roughly a hundred YAML files and several JSON inputs describe the same few ideas in overlapping ways, and several describe a database model that no longer exists. Success means one approved design per file type, one generated source of truth for table shapes, a rewritten manifest package that validates every seed file against both, and every stale input retired or archived with a record of why.

# Why this matters

The generated PostgreSQL schema has 94 tables, but `source/schema/contracts/targets.json` still lists about 120 from an older model. The five CSV files under `seed/global/auth/` were written for that older model, and about 60 mapping files under `seed/countries/ke/mappings/` target tables that no longer exist. The manifest validator checks paths and hashes but never checks a CSV column against a real table. The workers phase is also blocked because nothing resolves a source authority reference.

# Success measures

- Each YAML and JSON file type has one approved design, one schema, and one named owner in code.
- Table schemas for seeds are generated by Dryv, one file per PostgreSQL schema, and nothing hand-maintains a second table catalogue.
- `uv run mzizi-manifest check` verifies every seed file against its schema and every CSV against its generated table schema, and fails on any mismatch.
- Stale schemas, mappings and seed inputs are removed or archived, and every README and design link is updated.
- No task in this group is started until its design has been approved by the owner in a task comment.
