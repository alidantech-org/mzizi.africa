# Continue implementation and verify the product

## Approach

Three agents work in parallel with separate ownership: backend reads and contract defects, Flutter screens, and web screens. The coordinating agent owns runtime service health, Android installation and screenshots, browser inspection, cross-surface checks and the final evidence report. Existing implementation is audited before changing it, and backend API shapes remain stable where possible so frontend work can proceed immediately.

## Milestones

Verify the existing API and services, correct backend edge cases, finish mobile navigation and content screens, connect web governance and comparison, then install the app and inspect real screens. Finish with targeted checks, the full repository quality suite and accurate documentation.

## Risks and constraints

The working tree contains substantial changes from earlier work. Avoid concurrent edits to shared generated files, branches, worktrees and destructive database rebuilds. Root seed files require separate owner approval. Real social posts, photographs, legal provisions and unavailable statistical data cannot be invented; those gaps must remain visible while the software handles them consistently.
