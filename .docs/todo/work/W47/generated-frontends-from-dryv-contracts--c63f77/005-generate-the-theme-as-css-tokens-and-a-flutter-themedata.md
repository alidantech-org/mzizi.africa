# Generate the theme as CSS tokens and a Flutter ThemeData

## Goal

Make `brand.Mzizi` actually reach the frontends. The official `nextjs-app` and `flutter-app` packs ignore the theme, so the generated Flutter app uses a stock indigo seed and the Next.js apps have no tokens at all. Two small project packs read the application's resolved theme and write a CSS file (every foundation token as a custom property, the semantic roles, a dark mode, and a Tailwind v4 mapping) and a Dart file (token constants plus light and dark `ThemeData`). Colours, type, radii and shadows are then defined in one contract and nowhere else.

## Context

Dryv exposes the selected theme to packs as `application.theme` with tokens, roles and modes, and a pack with an empty template selection renders once per application (Dryv's own `examples/nextjs-app-router` and `examples/flutter-app-router` packs do this). Token values arrive as JSON text and Jinja has a `fromjson` filter. The contract is `dryv/contracts/schemas/theme.ts`; the target apps are `source/apps/web`, `source/apps/dev` and `source/apps/app`, generated by the wiring in `dryv.yaml`. The `www` landing page keeps its own hand-written CSS for now. The Next.js apps still lack `package.json` and a layout, so importing the CSS is a follow-up. Project packs live in `dryv/packs`.

## Progress

Two project packs, `dryv/packs/theme-css` and `dryv/packs/theme-dart`, render `application.theme` with an empty template selection. Generated: `source/apps/web/app/theme.css`, `source/apps/dev/app/theme.css` and `source/apps/app/lib/core/theme/mzizi_theme.dart`. The Flutter `main.dart` (scaffolded once, app-owned) now uses `buildMziziLightTheme()`, `buildMziziDarkTheme()` and `ThemeMode.system`; `flutter analyze` reports nothing from the theme file (the remaining errors are the earlier bridge ones).

## Notes

- The Jinja helpers are restricted: no string methods and no iterating a string, so kebab-case names are produced by a chained `replace`.
- The CSS and Dart files are not loaded by any running app yet: the Next.js apps still have no `package.json` or layout to import `theme.css`, and I have not run the Flutter app.
- CSS dimensions print as `20.0px`; valid, but the value is a float. Dryv's shadow token carries one layer, so www's two-layer shadows are approximated.
- The `www` landing page still has its own hand-written variables; it can import the generated file later.
- Not verified: the CSS has not been compiled by Tailwind.
