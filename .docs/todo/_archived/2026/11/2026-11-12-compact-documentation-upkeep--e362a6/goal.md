# Compact documentation upkeep

Keep Mzizi's current project documentation concise at the entry point, grouped by design concern, and accurate against the active repository. The eight `.docs/docs/` root documents describe purpose, goals, story, system, architecture, domains and roadmap. Detailed technical designs belong under `.docs/design/`, grouped into a small number of broad topics. Contributor and agent process belongs under `.docs/rules/`; `.docs/guidance/` must not return. Planning proposals have a separate home at `.docs/_plan/` and must not be described as implemented behavior. Success means links and path references resolve, the structure check enforces these boundaries, and documentation validation results are recorded with the work.
