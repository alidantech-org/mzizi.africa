# Decision: PostGIS and JSONB handling

Date: 2026-11-02.

## Finding

The Dryv `typeorm` pack maps records, composites and unknown types to `jsonb` (see the pack README and entity template). It has no geometry mapping, so PostGIS geometry cannot be expressed by the generated entity. The pack test (`bun sdk/scripts/test-pack.ts typeorm`) passes at the pinned ref.

## Decision

- JSONB fields are generated by Dryv as-is.
- Boundary geometry is declared in contracts as a GeoJSON record, so the generated entity holds it as `jsonb`, as the legacy `geo_boundary_versions` already does.
- Spatial indexing and PostGIS geometry columns belong to the database management engine: it adds a derived `geometry` column and GiST index from the JSONB source. The API reads them through a hand-written service using raw spatial queries on a read-only role.
- If this proves too limiting, extend the Dryv pack in a separate change and bump the pin.

## Consequences

The API never owns schema. Geometry stays a derived, rebuildable representation of the evidence-bearing GeoJSON.
